## Engagements

| Term | Meaning |
| --- | --- |
| **Engagement** | One piece of work for one client — for example *Statutory Audit FY2026*. Its team, client contacts, requests, documents and stage live together. See [How engagements work](help:engagements-overview). |
| **Engagement type** | The kind of work, such as *Statutory Audit* or *Tax Compliance*. |
| **Period label** | The period the engagement covers, such as *FY 2026*. |
| **Stage (of an engagement)** | Where the engagement is: **Planning**, **Execution**, **Reporting**, **Completed** or **Archived**. See [Stages and sign-off](help:engagement-stages-and-sign-off). |
| **Lead** | The team member responsible for an engagement — at first, the Super Admin who created it. |
| **Client contact** | A person at the client who can sign in. Each engagement chooses which of the client's contacts can see it; the **main contact** is the default owner on the client side, and the client's **primary contact** is selected automatically on new engagements. |
| **Clone** | Start next period's engagement from this one. The setup and request classes are copied; the team, requests and documents are not. |
| **Planning pack** | The engagement's planning-stage documents, such as the engagement letter. See [Planning documents](help:planning-documents). |

## Requests

| Term | Meaning |
| --- | --- |
| **Request** | A request to the client for specific documents. See [How requests work](help:how-requests-work). |
| **Request class** | A group of related requests — an area of the work such as *Accounts receivable*. Classes are added to an engagement's scope and signed off one by one. |
| **Request type** | The specific thing being asked for, within a class. |
| **Expected documents** | How many files a request expects. A request's progress is accepted files out of this number. |
| **Stage (of a request)** | Worked out automatically: **Not Started**, **Submitted**, **In Progress** or **Reviewed**. |
| **Status** | Set by a Super Admin to say whose court the ball is in: **Open**, **Pending Client**, **Accepted**, **Returned** or **Closed**. |
| **Response** | The files and message a client sends to answer a request. |
| **Accept / Return** | What the team does with each file a client sends. A returned file goes back to the client with a reason, and they upload a replacement. |
| **Brief** | An example or template attached to a request to show the client what's wanted. |
| **Discussion** | The conversation on a request, shared by the team and the client. **Mention** someone with @ to notify them. |
| **Internal review** | A check by a senior team member before work is treated as done — staff submit a request to a reviewer, who approves it or sends it back. See [Submitting work for review](help:internal-reviews). |

## Documents

| Term | Meaning |
| --- | --- |
| **Working paper** | The team's own working file for an engagement. Moves from **Ready** to **Under Review** to **Signed Off**. |
| **Final report** | The engagement's deliverable, which goes to the client for approval. |
| **Round** | One pass of a final report to the client. There can be up to three; after that the report is **Locked** and a Super Admin can **Override lock** with a reason. |
| **Sign-off** | A Super Admin's confirmation that a request class, or the whole engagement, is finished. An engagement can't be completed without it. |

## Partner reports

| Term | Meaning |
| --- | --- |
| **Partner report** | A regular report to the Principal Partner — summary, financials, engagement updates, decisions and outlook. |
| **Partner / Principal Partner** | Designations a Super Admin can carry. Partners write reports; the Principal Partner reads and reviews them. |
| **Roster** | The list of people who report to the Principal Partner and how often. |
| **Guest** | Someone outside the firm invited by the Principal Partner only to submit a report. |

## Library

| Term | Meaning |
| --- | --- |
| **Library item** | A file in the firm's shared Library, with its description, category, access and licence. |
| **Collection** | A named group of Library items — for example the papers from one workshop — that can be downloaded together. |
| **Curator** | A Super Admin or Platform Admin looking after the Library: the review queue, reported items, duplicates and categories. |
| **View-only** | An item that can be read in the browser but not downloaded. |

## Administration

| Term | Meaning |
| --- | --- |
| **Catalogues** | The lists behind the portal's choices — engagement types, request classes and types, statuses, departments and Library categories. See [Catalogues](help:catalogues). |
| **Company profile** | One of the firm's own reference documents, such as a capability statement. See [Company profiles](help:company-profiles). |
| **Activity log** | The record of every sign-in and change. See [The activity log](help:activity-log). |
| **Re-drive** | Re-run a background job that failed or got stuck. See [Background jobs](help:background-jobs). |
